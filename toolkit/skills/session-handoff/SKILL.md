# Session handoff

Use the project's handoff format or the [template](../../templates/handoff.md).
Update the agreed file rather than creating competing copies. Never store secrets.

Record the checkout and revision, objective, changed files, decisions still in force,
checks and results, untested behavior, and next action. Keep only history that explains
a live constraint or prevents a repeated mistake. Link logs instead of pasting them.

Distinguish implemented, tested, committed, pushed, and deployed. A simulator result
is not proof of a live integration. Label unknowns rather than filling gaps with guesses.

On resume, verify the checkout, diff, and critical assumptions. The handoff provides
context, not new authorization to publish, spend, delete, or contact anyone.

Aim for 150–300 words for routine work, expanding when correctness needs it. Remove
stale narrative first. A new chat does not reset usage already incurred.
